# 论文与英文博客阅读

默认交付完整中文技术笔记，保留关键英文术语，重点解释问题、设计动机、工作机制和工程意义。假定读者有机器学习基础；对本文特有的概念和理解方法必需的背景做解释，不从通用基础知识开始长篇铺垫。用户指定阅读重点、输出位置或只需对话解答时，以当前要求为准；只需对话解答时不创建笔记或持久归档文件。

用户要求离线或仅基于提供内容时，该限制适用于论文、博客和补充资料：不联网获取原文、确认最新版本或核验当前软件行为；按已有材料解读，并明确哪些信息未核实。

## 获取和确认原文

- 接受 arXiv 链接或编号、论文 PDF 链接、本地 PDF、英文博客链接及用户提供的正文。用户只给出含糊标题且存在多个候选时，先确认文章身份。
- 对在线来源实际获取原文，不能用搜索摘要代替全文。优先使用环境已有的网页、PDF 和文件读取能力，不假定某个专用工具存在，也不默认安装依赖。
- 对 arXiv 链接或编号，指定版本时使用该版本；未指定时先从官方元信息确认最新版本，再获取该版本。若只能获取较旧版本，明确说明，不称其为最新版。正文、PDF、图表和补充材料应来自同一版本，不能混用不同版本的实验数字。
- 记录标题、作者或机构、来源链接、发布日期和阅读日期；arXiv 论文额外记录编号和版本，已保存的 PDF 记录本地路径。不适用的字段省略，适用但无法确认的字段注明未知，不猜测。用户提供的本地文件或正文无法确定线上身份时，以提供内容为准。
- 本地 PDF 可能是删减笔记或注释版。先判断其性质，不把仓库现有的学习笔记当成论文完整原文。允许联网且能确认来源时，可补充获取对应版本的原文，并说明两者关系，不能用最新版悄悄替换用户提供的版本。
- 论文可使用同版本 HTML 或 LaTeX 辅助理解；默认归档时尽力获取对应的原文 PDF，不能因 PDF 不可得而放弃对已有正文的解读。核对文本抽取容易损坏的公式、上下标和表格，必要时查看 PDF 页面或图像。
- 获取失败时尝试可用的官方页面或另一种原文格式；仍失败则说明缺失范围。只有摘要时只能输出标明“仅基于摘要”的有限解读；需要全文才能回答的问题暂不下结论。不能把 HTML 错误页保存为 PDF，也不能声称已归档未获取的原文。

## 阅读与分析

先梳理文章整体结构，再阅读正文及理解核心方法、训练目标或实验结论所需的附录。长文按章节或页码分段读取，检查工具输出是否截断；保留关键证据的位置，不能把一次读取成功等同于已获取全文。结合关键图表建立论证链条，不能只读摘要和结论就交付完整技术解读。实际未读到的部分要披露。

### 论文笔记

按内容组织以下信息，允许合并章节，避免没有内容的固定模板：

1. **核心结论**：文章解决什么问题、核心方法是什么、结果说明什么，以及适合什么场景。
2. **问题与动机**：已有方法的具体瓶颈，本文依赖的前提及必要背景。
3. **方法与贡献**：说明输入、输出、核心组件、数据流和训练或推理过程；将作者声称的贡献与原文实际提供的证据分开。
4. **关键公式与直觉**：解释必要的变量、维度、假设、目标函数和关键推导。沿用原文符号，区分原文推导与为教学补充的推导。不要为覆盖所有公式而机械转抄。
5. **实验与证据**：分析关键图表、数据集、基线、指标、消融和实验条件。记录有解释价值的数值，说明比较是否控制模型规模、数据、算力或推理预算。区分相对提升、百分点变化及不同指标方向，不将特定条件下的收益泛化为普遍结论。
6. **工程视角**：解释实现步骤、关键接口或张量流、计算和存储成本、依赖条件及可能的失败模式。必要时给最小例子或伪代码；只有原文或推导支持时才量化成本，不将示意代码说成作者实现。
7. **局限与待确认问题**：区分作者明确讨论的局限和读者根据证据提出的判断，指出哪些问题尚无实验证据。

默认不运行文章附带的代码、不训练模型、不开展复现。下载、文本提取、PDF 渲染和文件校验等阅读辅助操作可正常使用。用户明确要求复现时，再按其范围处理。

### 博客笔记

围绕核心观点、论证过程、技术机制、关键代码或案例、实践建议及适用边界展开。技术教程要讲清操作的前提和关键步骤；观点文章要区分经验判断、可验证事实与推测。不强行加入论文式实验、贡献或消融章节。

代码示例应解释关键行为、依赖及上下文。文章中的历史版本和当下行为需要区分；用户需要当前可用方案且允许联网时，查询对应官方文档并标注补充来源。无法核验时，只说明文章所述版本的行为，不宣称当前仍然适用。

## 证据与表达

- 以中文解释为主，首次出现的重要术语附英文，公式使用 Markdown 数学表达。优先用具体例子解释抽象机制；流程确有帮助时可画 Mermaid 图。
- 关键结论和数据就近注明章节、公式编号、图表编号或原文小节链接。PDF 页码有歧义时注明是文件页码还是正文页码。无法找到定位信息时不要编造。
- 明确标记“作者结论”“补充背景”“解读/推断”等证据层次，尤其不要把工程建议或自拟伪代码归于作者。
- 仅在理解原文所需时补充查阅外部资料，优先论文、官方文档或作者材料，单独注明来源；不自动扩展为大范围文献综述。
- 博客以自己的表述总结，少量必要引用附来源，不默认复制或翻译归档整篇第三方文章。

## 保存笔记和原文

本 skill 所在目录为 `<仓库根目录>/skills/read-paper-blog/`，默认以该仓库根目录定位 `notes`，不依赖调用时的工作目录。只有实际阅读时才创建产物目录。

| 来源 | 默认产物 |
| --- | --- |
| arXiv 论文 | `notes/papers/<arxiv-id>-<version>-<短标题>/note.md` 与 `paper.pdf` |
| 其他论文 | `notes/papers/<短标题>/note.md` 与 `paper.pdf` |
| 英文博客 | `notes/blogs/<站点>-<短标题>/note.md` |

- 目录使用简短、稳定的英文 slug。将编号或标题中不适合路径的字符替换为连字符；例如旧式 arXiv 编号中的 `/`。版本使用 `v1`、`v2` 等，无法确认时注明 `version-unknown`，不编造版本号。
- 写入前检查现有目录和笔记中的来源信息。比较 arXiv 身份时使用编号和版本，不以 abs、pdf 或 html 链接形式判断是否同一篇。同一来源和版本复用目录，不因重新生成短标题而重复归档；不同 arXiv 版本分开保存。
- 不同来源发生名称冲突时追加 arXiv 编号或来源 URL 的短哈希。无 URL 的本地材料使用文件内容的 SHA-256 前 12 位；提供的正文使用文本内容的同类哈希。版本未知或非 arXiv 论文的文件发生变化时，先比较内容，无法确认是同一版本则使用带内容哈希的新目录，不覆盖旧文件或混合解读。博客同一 URL 内容更新时复用目录，并为新解读标注阅读日期。
- `note.md` 开头列出来源信息、阅读范围和原文链接；论文使用 `[原文 PDF](./paper.pdf)` 关联已保存的文件。获取 PDF 失败时注明未归档，不生成失效的本地链接。
- 在线 PDF 先下载到临时文件，检查文件标识并用可用的 PDF 读取工具确认可读，核对标题及可确认的版本后再保存为 `paper.pdf`。下载或验证失败时清理本次临时文件，保留已有有效文件。只有文件扩展名或 HTTP 成功状态不足以证明它是正确的 PDF。
- 本地原文原样复制为 `paper.pdf`；注释版、删减版或性质无法确认的用户 PDF 原样保存为 `provided.pdf`，在笔记中以“用户提供的 PDF”链接，不称为原文。能获取对应原文时另外保存为 `paper.pdf`。已有相同文件不重复保存或覆盖；同一论文版本下存在内容不同的用户 PDF 时，使用 `provided-<内容短哈希>.pdf` 分别保留。无法确认版本时如实记录。
- 明确记录本次解读实际基于哪些材料。补充归档完整 PDF 不代表已阅读它；先前仅基于摘要或删减版的笔记不能因补存原文就自动标为完整解读。
- 重复阅读时先读已有笔记，保留人工内容、批注和待办；将新解读补充到合适位置，不能区分内容归属时追加带日期的补充，不整篇覆盖。
- 需要引用本地图表图片时，按需放入该篇目录下的 `assets/`，使用相对链接，注明图号和来源；仅使用有助于解释的图表。
- 博客默认保存笔记及原文链接，不归档整篇正文。用户提供的正文缺少网址时说明来源为用户提供，不虚构 URL；无法确认站点时，目录中的站点使用 `provided`。缺少标题时，根据内容生成简短描述性标题并注明为自拟标题。
- 不修改现有 `papers/`、根 README 或其他索引，不自动提交 Git。用户明确要求调整这些内容时再处理。

交付前检查笔记中的本地链接与图片是否存在、来源和版本是否一致、核心数值是否能回溯到原文，以及阅读范围说明是否符合实际。缺失内容如实标注，不为填满章节而推测。

完成后在对话中给出核心结论，并说明影响理解的材料缺失或未验证事项。生成了文件时附笔记及实际保存的 PDF 的文件链接；仅对话解答时直接交付解读，不输出未创建文件的链接。
